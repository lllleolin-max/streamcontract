# State, cost and recovery

`contract.py` compiles strict fields, time policy, resource bounds and aggregate checks. `engine.py` is a single-thread state machine with exact rational moments per numeric field per `(window, hashed group)`. `moments.py` constructs and validates bounded enum-frequency/binary-lattice realizability witnesses. `cli.py` incrementally reads bounded lines, emits JSONL and verifies source-prefix identity on restore. Event payload references are released at the end of each push.

Each accepted event is assigned to `floor(t / size) * size`. Against the previous watermark W, `W >= end + lateness` yields LATE without advancing W. Otherwise preflight checks state limits, accumulates moments, advances maximum timestamp, computes W, and finalizes all windows whose deadlines are `<= W`. Finalization is once-only; no results are emitted before the lateness budget expires. EOF explicitly finalizes observed windows even if their deadlines have not been reached. Invalid shape/parser events consume a sequence but do not influence maximum time. A resource exception is transactional: no counters, watermark, active state or sequence change.

Let W be max active windows, G max groups per window, F numeric fields including mandatory event time, E max witness entries per field, R aggregate rules, B bounded record bytes. E is 1 for integer fields, <=256 for enum fields and <=min(configured stratum cap,2147) for other number fields. Retained state is O(W*G*F*E), plus contract and counters; each exact numeric rational has a bounded finite-float exponent and count-derived numerator size. Normal push costs O(B + W + F), closure O(W log W + closed groups*R); sorted output is deterministic. Checkpoint serialization costs O(W*G*F*E) plus sorting; restore scans those witnesses, without expanding sample counts or solving subset-sum. When all grouping fields have retained numeric witnesses, hash identity validation enumerates at most 2**8 legal integer/float representations. JSON encoding temporarily duplicates bounded state. Prefix verification costs O(consumed input bytes) and uses O(B) read memory. Output lists can contain O(W*G*R) finalization evidence; retained output memory is the caller's responsibility. Limits are not a byte-perfect total process memory cap.

Checkpoint format v3 binds exact contract digest, consumed sequence, maximum time, watermark, counters, finished flag, active boundaries, hashed groups and rational moments with bounded realizability witnesses. Envelope SHA-256 detects accidental corruption; restore additionally validates accepted-event conservation, each field's full primitive/enum/range domain and witness reconstruction, mandatory event-time bounds inside `[start,end)` and <= global maximum, maximum equality with retained time evidence, and the fixed no-group hash. Aggregated event time must equal the mandatory time witness; numeric grouping aggregates must be constant and known numeric key representations match the group digest. See [the constructive proof](NUMERIC_WITNESSES.md). v1/v2 reject rather than silently migrate. CLI metadata binds consumed line count and SHA-256 of exact input prefix, including whitespace/newlines and rejected lines. No source pathname or raw record is stored. A changed contract, damaged checksum, impossible witnessed numeric/time state, wrong expected SDK sequence or altered/shorter consumed prefix fails closed.

Recovery guarantee: for the same parsed input order, same contract and valid boundary, concatenating the decisions around a checkpoint equals uninterrupted decisions; rational serialization does not round the accumulator. The CLI rereads consumed lines rather than trusting a byte offset. A growing source may append records after a paused checkpoint; the consumed prefix must remain fixed.

Persistence boundaries: `save` writes in the destination directory, flushes/fsyncs the temporary file and atomically replaces. Directory fsync/power-loss guarantees vary by OS/filesystem and are not claimed. Decision stdout and checkpoint replacement are **not one transaction**: a crash after output but before save may replay decisions, and after save but before output consumption may leave a sink behind. Use sequence plus window/group/contract IDs as downstream idempotency keys and transact your own sink/cursor. No Kafka multi-partition checkpoint coordination, sink acknowledgment, exactly-once delivery, encryption or hostile-actor authentication is provided. SDK calls are not thread-safe; one engine per ordered lane.

Watermarks are a declared disorder assumption, not an observed truth. A far-future accepted timestamp closes older windows; later old records are quarantined. Invalid records cannot do that, but valid incorrect timestamps can. Choose producer clock bounds upstream. No expected-group list exists, so a group that never sends data and entirely empty time intervals remain unobserved. There are no time-based idle triggers; stalled input requires explicit EOF or upstream lifecycle decisions.
